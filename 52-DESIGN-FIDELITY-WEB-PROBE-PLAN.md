## Problem — the design-fidelity runtime gate passes vacuously on every real design source

Plan 40 made visual drift gate-blocking via a `data-ref`-keyed disposition manifest (`specs/[feature]/design-manifest.json`, produced at `/breakdown` PHASE 2.5) that two downstream gates consume: the static `verify-design-tokens` Check 5 (`/implement`) and the runtime `design-auditor` conformance dispatch (`/review`). Plan 40 OQ-5 **required `data-ref` anchors** on impl elements corresponding to reference elements and **rejected fuzzy DOM matching**; OQ-1 resolved the runtime mechanism to a **hybrid computed-style + screenshot-diff scoped to declared MATCH regions**.

**No real design source produces `data-ref`.** Confirmed in a consumer install (mintEnvoy, `specs/015-request-sub-tabs`) 2026-07-06:

- `design/reference.html` is a 1.6M Claude Design export carrying `data-mstyle` / `data-theme` / `data-sidebar` inline-style keys — **zero `class=`, zero `data-ref`**. Figma exports, hand-authored mocks, and Claude Code exports likewise never emit `data-ref`. Re-anchoring every re-export by hand is a workflow nobody sustains.
- So `resolve-reference` finds zero anchors → `init-manifest` produces `elements: []` → `validate-manifest` treats empty-elements + empty-gap-list as **VALID, exit 0** → the runtime gate has nothing to check → **verdict PASS**. Chrome MCP was AVAILABLE; the gate still passed vacuously. The user saw real visual mismatches while the gate reported green.
- The false-green is confirmed in code (this session's investigation): the static Check 5 early-returns `[]` on empty `match_refs` (`_scanner.py:716`), and `emit_findings` maps zero findings → `EXIT_CLEAN` with **no SKIPPED/N/A verdict state** (`_shared.py:105`). A PASS is indistinguishable from "nothing was checked." The runtime `design-auditor` at least SKIPs explicitly (`design-auditor.md:37`) but declares "not covered" only for the Chrome-MCP-absent case (`:52`), not the empty-manifest case — so the empty-manifest skip is under-declared and still yields PASS.

**The apparatus is orthogonal dead weight sitting next to two real reference artifacts it ignores.** mintEnvoy evolved its own working discipline that bypasses the manifest entirely:

- `design/design-fidelity-contract.md` — a curated MENU of authentic resolved token values from `styles.css` (per-token, per-theme, per-element: `.pane-tab` height/gap/colour/weight, `.badge`, grid-templates), explicitly fed into `/specify` AC-13 → Playwright CT `getComputedStyle` assertions. The framework knows nothing about it.
- `design/reference-screenshot.png` — a 1936×1276 canonical full-app render. The framework never looks at it.

The working CT path catches **discrete token values on an isolated component**. It structurally cannot catch **assembled-app layout / overflow / composition drift** (CT mounts the component isolated, with no real siblings, container width, or data lengths) — which is the class of defect that caused the visual regression here.

## The mechanism — read the running assembled app, not the reference DOM/pixels

Both reference-side artifacts are unusable for an automated runtime gate: `reference.html` is programmatically unmatchable (no anchors/classes), and `reference-screenshot.png` is a full-app mock with different data — even cropped to a small feature region, a pixel diff drowns in mock-vs-live content noise. **Screenshot-diff is retired.**

The one thing that works on **built** UI is reading the running assembled app directly (`design-auditor` already carries `mcp__chrome-devtools__evaluate_script` post-plan-40). The gate becomes two passes at `/review`:

### Pass 1 — Always-on geometry (deterministic, universal floor, zero value-source dependency)

- A **shipped JS probe**, run via `evaluate_script`, walks the feature region and returns **structured findings JSON**. The LLM orchestrates and reports — it **never eyeballs geometry** (an LLM eyeballing geometry is itself unreliable; the always-on half is deterministic by construction).
- **Default invariants — narrow, computed-style-gated (catch only unambiguous defects):**
  - **Unintended horizontal overflow:** `scrollWidth > clientWidth` **AND** computed `overflow-x ∈ {visible, hidden}`. Exempt `overflow-x ∈ {auto, scroll}` (intentional scroll containers — code blocks, tables, carousels).
  - **Clipping:** child rect ⊄ parent rect **AND** parent computed `overflow ∈ {hidden, clip, auto}` (parent actually cuts) **AND** child computed `position ∈ {static, relative}`. Exempt `position ∈ {absolute, fixed}` (dropdowns / tooltips / popovers escaping by design).
  - **Font-not-loaded (D12 Mode 2 — the only catcher after screenshot-diff retired):** for each font-family the region/root DECLARES, `document.fonts.check('<size> <family>')` must return true. Target the **first QUOTED family** in each stack (e.g. `"Inter"`, `"JetBrains Mono"`) — the webfont that can actually fail; SKIP generic/system keywords (`-apple-system`, `system-ui`, `sans-serif`), which are always "available" and would pass vacuously (a new false-green — the fallback IS what masks the bug). A declared-but-unavailable family → a distinct `font-not-loaded` finding. This is deterministic DOM math (fits the non-LLM probe) and reference-free — `getComputedStyle` CANNOT catch it, because the declaration `"Inter", …` survives the silent fallback. Check **every custom family the DOM/source actually declares** — NOT a fixed sans+mono pair (a project may declare one font, or three, under any token names; the set is read, not hardcoded).
- **Opt-in per-feature strictness flags** (NOT defaults — many components legitimately wrap or overflow-by-design): `single-row` / `no-wrap`, `strict-containment`.
- **Scoped to the feature's `region_selector`** (its subtree), NOT page-wide — avoids flagging unrelated pre-existing page defects and keeps `/review` feature-scoped.
- Lock-in-free: pure DOM math on the assembled app — no Claude Design, no `styles.css`, no contract. Generalizes to every project; it is the universal floor.

### Pass 2 — Value-fidelity (presence-gated layer)

- Active **only when a value source exists**: `design/styles.css` `:root` tokens, or a `design-fidelity-contract.md`. Source absent → this layer is silently N/A (geometry still runs).
- Reads computed style of the region and asserts against the declared token values (resolve `var(--x)` → the token's declared value). LLM judgment legitimately lives here (resolve-and-compare, per-theme).
- **Mandatory root-font assertion (D12 Mode 1), independent of the feature's `value_refs`:** whenever a value source exists, ALWAYS assert the root/body computed `font-family` resolves to the **project's declared primary font token — read FROM the value source, NOT a hardcoded token name — and not a browser/system fallback**, regardless of what the feature declared. (The framework does NOT assume mintEnvoy's `--font-sans`/`--font-mono` scheme; a project may name its tokens `--font-body`/`--font-code`, declare one family or three — the probe reads which token the source binds to root/body and asserts the render matches it.) Rationale (mirrors always-on geometry): the primary/body font is the *inherited default* — designs declare `font-family` mostly on secondary islands (code/values/url), rarely on the primary surface, so a per-feature `value_refs` almost never lists it. That omission is exactly how a wrong-root-font ships green through BOTH this value-pass AND the existing CT (both key off the same source). The most-easily-omitted global property must not depend on someone remembering to declare it. Secondary-font *assignment* stays per-context (a mono/code font is applied to specific islands — you cannot assert it everywhere); every declared font's *load* is covered by Pass 1's font-not-loaded check.
- mintEnvoy gets this layer for free because it has the contract; a bare project gets geometry-only (+ Pass 1's reference-free font-load check). Either way a **real** check always runs.

### The per-feature declaration — reframed `design-manifest.json`

Replaces the `data-ref` element list with a **`kind`-tagged `target`** (the platform-variant point, D13 — so the schema anticipates non-web from the start rather than baking CSS-selector assumptions into the core):

```
targets: [ { target: { kind: "web", route, region_selector }, geometry_flags?, value_refs? } ]
```

- `target.kind` is an **OPEN discriminator, NOT an enum.** The framework implements exactly `kind: "web"` (`route` + CSS `region_selector`). It does NOT enumerate or reserve future platform names — the rule is "**non-`web` → NOT-COVERED (honesty #7)**," generically, whatever the kind string is (the next platform might be anything; naming it now would bake a guess into the schema). The validator accepts any `kind` string as shape-valid; only the `web` arm has field requirements + a probe; any non-`web` kind → NOT-COVERED at probe time, never a schema error that blocks the pipeline.
- On web, `route` + `region_selector` = "where the feature renders" — the irreducible target. A selector without a route is meaningless ("check `.request-pane`" needs "on which screen"); the two together complete the target. This adds no manifest — it completes the selector the declaration already needed.
- Declared at `/breakdown` intake (a promise: the engineer adds the `region_selector` testid; the feature renders at `route`), verified at `/review`. Far more natural than `data-ref` — a testid + a screen are normal practice, not annotations on a 1.6M export.
- `geometry_flags` (opt-in strictness) and `value_refs` (contract §-refs / token names) are optional and platform-agnostic (a future non-web probe consumes the same two fields).

## Honesty invariants — kill the false-green by construction, not by discipline

Always-on guarantees a real check ran, so PASS never means "nothing was checked." The full NOT-COVERED set (each is loud, never a silent PASS, never a spurious FAIL):

1. **Chrome MCP absent** → NOT-COVERED (carried from plan 40 OQ-3).
2. **`route` absent** in the target → NOT-COVERED (don't infer the screen — a misinferred route runs the deterministic probe on the wrong surface and returns clean: a "correctly-checked, wrong-place" false-green).
3. **`region_selector` absent** in the target → NOT-COVERED.
4. **`region_selector` not found / region not mounted** → NOT-COVERED. Isolate-first builds mount a component via its owner later (e.g. `KVTable` exists but `panes.request` hasn't wired it in yet); selector-not-found is **not checked** (loud), **not clean** (the "0 elements = 0 findings = green" trap one level in), and **not a defect** (absence ≠ overflow).
5. **Legacy `data-ref` / empty-targets manifest** → NOT-COVERED (never the current silent exit-0 PASS).
6. **PASS is emittable ONLY when the geometry probe actually executed against a FOUND region.**
7. **Platform mismatch** (the feature's package stack is non-web / the `target.kind` is not `web`, or is unimplemented) → NOT-COVERED (`platform: non-web, DOM gate N/A`), never PASS, never crash. **Evaluated FIRST — the outermost preflight, before #1** (on a non-web target you do not even attempt the DOM probe); numbered last only to preserve the existing #4/#5 cross-references. Detection reuses existing stack metadata (`PACKAGE_STACKS` / `/configure` / constitution), per-feature/package — NOT a new detector. A canvas-rendering web framework (one `<canvas>`, no per-element DOM to query) is caught up front by stack where detectable, and #4 (region-not-found) backstops it at probe time regardless.

The overflow / clip / **font-not-loaded** (Pass 1) and root-font / token mismatches (Pass 2) are DEFECT findings, not NOT-COVERED conditions — they are real failures the probe raises against a found region; only #1–#5 + #7 gate the coverage verdict.

**Known limitation — geometry reflects the RENDERED state (documented, not a blocker).** Overflow/clip depend on content: a KV table with 2 rows doesn't overflow; with 50 it might. An empty/seed-less app can hide a real geometry defect (probe clean → breaks on real data — a false-negative). The report must state: *"the geometry pass reflects the rendered state; sparse/empty state may not exercise overflow/wrap — a representative seed is recommended for features whose layout is data-dependent."* A green geometry on an empty app means "didn't overflow on this data," not "layout safe."

## Settled decisions (ratified this session)

- **D1 — Read the assembled running app, not the reference DOM/pixels.** `reference.html` (unmatchable) and `reference-screenshot.png` (full-app, wrong data) are retired from the automated gate; they remain human reference docs.
- **D2 — Always-on geometry pass, presence-gated value-fidelity layer.** The asymmetry is the framework shape: geometry needs nothing → universal floor → always-on; value-fidelity needs a declared source → layered → active-when-present. Non-vacuousness is structural, not procedural.
- **D3 — Geometry is a deterministic JS probe, not LLM judgment.** Shipped `evaluate_script` payload returning structured findings; LLM orchestrates/reports only.
- **D4 — Narrow default invariant set** (unintended overflow + clipping, both computed-style-gated); `single-row`/`no-wrap` and `strict-containment` are per-feature opt-in flags, not defaults.
- **D5 — Region-scoped, not page-wide** — keeps `/review` feature-scoped, avoids flagging unrelated pre-existing defects.
- **D6 — Explicit `route` in the declaration, never inferred** (honesty invariant #2); `route`/`region_selector` absent or not-found → NOT-COVERED.
- **D7 — Reuse the existing pipeline slots** (manifest produced at `/breakdown`, runtime gate at `/review`); reframe the manifest schema rather than build a parallel path (Integration decision A).
- **D8 — Value-fidelity is presence-gated on a token/contract source** — framework-general; mintEnvoy's `contract.md` qualifies but is not required (Integration decision B).
- **D9 — Retire static Check 5** (MATCH token-binding — a `data-ref` proxy). **Keep Checks 1–4** (hardcoded-literal ban; static at `/implement`; manifest-independent; untouched).
- **D10 — This supersedes plan 40 OQ-1 (hybrid screenshot) + OQ-5 (data-ref).** Plan 43's non-file-source declare-and-warn stays but its relevance shrinks (the gate no longer depends on a parseable reference). Plan 42's `verify-manifest-present` trigger backstop is retargeted (reference-present ⇒ ≥1 valid target, not a non-empty `data-ref` element list).
- **D11 — Documented narrowing: value-fidelity trusts a declared value source as the reference proxy, NOT `design/reference.html` directly.** After this ships NO automated check reads `reference.html`; value-fidelity asserts computed style against `styles.css`/`contract.md`. This is defensible — the contract/tokens are *extracted from* the design export (in mintEnvoy, `contract.md` is a curated read of `styles.css`, itself the Claude Design export) — but it IS a narrowing of the plan-40 "match the reference 1:1" guarantee. Accepted deliberately; `src/constitution.md` §3.8 must be reworded to state it (Phase 7), not left asserting the old guarantee.
- **D12 — Font drift has two modes; each gets a home, no third pass.** Mode 1 (wrong root font — the primary/body text falls to a system font) → a **mandatory root-font assertion in Pass 2**, independent of `value_refs` (the sans default is the most-omitted global property; both the value-pass and the existing CT share the blind spot because both key off a contract that declares font mostly on mono islands). Mode 2 (declared-but-not-loaded — the webfont never loaded, `getComputedStyle` still returns the declared family) → a **`font-not-loaded` finding-type in Pass 1** via `document.fonts.check()`, targeting the first quoted/custom family (skip generics — they always resolve). Mode 2 is deterministic + reference-free; it restores what retiring screenshot-diff removed. The font DEFECT-TYPES (`font-not-loaded`, root-font mismatch) are platform-agnostic core concepts; only the DETECTION (`document.fonts.check()` reading CSS declarations) is web-probe-specific. A non-web probe's concrete font-load/font-family detection is named WHEN that probe is written, with the platform in hand — NOT baked into the contract now (the "second real consumer" rule). **The always-checked property is the CLASS — "root font-family resolves to a project-DECLARED font token, not a browser/system fallback" — NOT specific token names.** Which tokens are the font tokens is READ from the project's value source (mintEnvoy's `--font-sans`/`--font-mono` is one convention; a project may use `--font-body`/`--font-code`, one family or three, or any scheme). Hardcoding token names would bake one project's schema into the framework — the same one-example mis-abstraction D13 guards against, one level down. This keeps D12 platform- AND project-agnostic: the abstract defect is "declared primary font didn't render / a declared font didn't load," read from whatever source the platform+project use.
- **D13 — Design-fidelity splits into a platform-agnostic honesty-core + per-platform probes; decision (c) — factor the cheap seams now, defer the plugin core.** Non-web platforms are anticipated, so a web monolith would force a schema migration + core disentangle at first non-web contact. But a FULL factor-now is also wrong: you cannot derive the core's shape from one platform, and web is misleading about it — this plan RETIRES the pixel pass (mock-vs-live-data noise), yet a non-web platform may have a WORKING pixel pass (e.g. golden/snapshot tests with controlled data), so a core factored from web-only would bake in "no pixel half," which could be wrong for a non-web target. So (c): do NOW only the cheap-to-do / expensive-to-retrofit seams — honesty #7 (platform-mismatch → NOT-COVERED), the `kind`-tagged `target` schema (open discriminator — implement `web`, NOT-COVER everything else generically, enumerate NO future platform), and a separable web-probe/core boundary that reuses the existing `src/devforge/lib/_shared/` finding substrate (do NOT build a new plugin registry for one plugin). DEFER the abstract probe interface + the core's final shape to the first non-web probe plan, which extracts with two real probe shapes in hand — matching the framework's own `_shared/` sequencing (extracted at the SECOND consumer `/review`, not speculatively from `/audit`). That non-web plan is a NEW probe against the shared core (reading that platform's own introspection model, whatever it is), NOT an extension of the DOM probe — and it names the concrete platform then, with the platform in hand, not now.

## Phase 3 — Value-fidelity: declared-value extraction (presence-gated)
