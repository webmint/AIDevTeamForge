## The two gaps

### GAP 1 — mode gate

Phase 2.5b's trigger condition (1) is "bug mode", and check 17 is `bug_mode_17`-guarded. v2 ran in Enhancement mode, so **the whole lane was inert**. This is the identical defect plan 67 fixed for check 8 (caller enumeration was bug-only; plan 67 made it mode-independent). Dead-code-removal and cleanup tickets are TYPICALLY enhancement-classified — and those are precisely the tickets where literal provenance is load-bearing, because "is this still reached?" is the whole question.

### GAP 2 — trigger shape (the deeper gap)

Both existing trigger arms cover a literal that **IS the defect** or is **ABOUT TO BE REPLACED**. Neither covers a literal used as **evidence for a scope conclusion**:

- "the flag is hardcoded `false`, therefore this chain is dead" — v2's primary frame;
- "its only caller passes `true`, therefore this prop is live" — v2's fatal runner-up call.

In both, the literal is reasoned FROM; the plan is to **delete** or to **keep**, never to replace. Check 17's replacement-prose detector cannot match either. So **even a fully mode-decoupled Phase 2.5b would still have missed the prop** — GAP 1 alone does not fix the incident.

### Why the evidence arm is worth its cost: it is SYMMETRIC

The probe is not a bug-hunt bolted onto a cleanup ticket. Run on the same run's two load-bearing literals it points in opposite directions:

- on `isVariantItem = computed(() => false)` it surfaces TICKET-C "clean up variant-specific dependencies" and **CORROBORATES** v2's correct primary finding (the chain really is dead — and now with a dated commit behind it);
- on `is-variant-items` it surfaces TICKET-B and **BREAKS** v2's wrong runner-up finding.

A check that only ever weakens conclusions is a tax. This one adjudicates: it converts "the literal says X" into "the literal says X, and here is when and why it came to say X." That is the argument for adding it.

## Decisions (ratify at Phase 0)

### D1 — Decouple Phase 2.5b + check 17 from bug mode

**For.** Exact mirror of plan 67's shipped check-8 decouple, for the same reason: the auto-classifier (`_topic_conflicts.py` token lists) returns `None` for removal tickets, the human answers "enhancement", and a mandatory lane silently becomes optional. The failure class — a load-bearing gate that is mandatory for the ticket shape that least needs it and absent for the shape where the miss ships quietly — is identical.

**Counter (record it).** Enhancement runs now pay archaeology cost on every literal-involving ticket. Mitigation: trigger arm (2) still gates on a literal actually being involved — the decouple removes a mode conjunct, it does not make the lane unconditional. And plan 69 D6 recorded 17 + 2.5b as staying bug-gated on the "runtime-symptom machinery" rationale (for the record, explicitly not a ratification item); that rationale is TRUE for checks 15/16 and Phase 2.4d (they trace runtime symptom VALUES, which an enhancement has none of) but FALSE for 2.5b, which traces COMMIT HISTORY — history exists identically in both modes. **D1 corrects that recorded assumption for 17 + 2.5b ONLY**; 15/16 + 2.4d stay bug-gated, untouched.

**Blast radius is three sites, not two** (see Verified state): `main.md:708` trigger condition 1; `_cmds_render_verify.py:639` `bug_mode_17`; **and** `handoff_schema.py:940` `if mode == "bug" and is_literal_replacement:`. All three ship together in **Phase 1** — two of them Python, one of them consumer-facing prose, so that phase runs two agent loops, not one. Splitting them across phases leaves either the schema silently enforcing the old contract at `finalize-handoff` time or the spec telling the LLM to skip the lane the gate now demands.

### D2 — Add a THIRD trigger arm: literal-as-evidence

**For.** Fires when a finding's or a conclusion's grounds cite the **VALUE of a primitive literal** as the basis for a **scope call** (dead/live, in/out-of-scope, keep/delete). This is the arm that catches the incident; GAP 1 alone does not. Reuse the existing 6-value intent enum **unchanged** — `forgotten` and `inherited-refactor` are exactly what TICKET-B produced, so no new enum value is needed and the dedupe key `(literal, file_line)` plus the report render both stay as-is. `record-literal-archaeology`'s SIGNATURE is OQ-5's concern, not D2's: OQ-5 adds a required `--use` arg to it, and D2 neither needs nor forbids that.

**Counter (record it).** "Cites a literal's value as grounds for a scope call" is a fuzzier trigger than "replaces a literal" — an LLM can under-recognize it, and unlike arm (2) there is no downstream prose detector that can independently catch a miss (which is exactly why D4 supplies a mechanical carrier). Accepted: the arm's job is to widen the SEMANTIC trigger; D4 supplies the forcing.

### D3 — A new per-intent recovery arm for the evidence use

**For.** The existing per-intent recovery rules — "escalate the default one layer up", "propose the change in the generator template", "cite the SHA before overriding a deliberate choice" (`main.md` `753-758` **[author-reported]**; cited `:743-748` at drafting) — are ALL about **fix layer**. None applies when nothing is being replaced. New rule:

- `intent ∈ {placeholder, forgotten, inherited-refactor}` ⇒ **the literal's current value is NOT evidence of intent.** Any scope conclusion resting on it must be re-derived from another source (caller trace, the parent's own history, runtime probe) or **downgraded in confidence** in the report.
- `intent == deliberate` ⇒ the conclusion may stand, **but must cite the introducing commit SHA + subject** (the same evidentiary bar the existing `deliberate` rule imposes on overriding one). **[QUALIFIED 2026-08-14 by plan 75's Phase 1 — and read the next sentence before searching this file for the clause it changed.** This annotation **ADDS** a statement here; it does not correct one, because the clause that bounded archaeology to a single commit — `Multi-commit history is OUT OF SCOPE; anchor on the oldest` — lives in `src/commands/research/main.md` Phase 2.5b step 1 and **never appeared in this file at all** (verified 2026-08-14: `grep "OUT OF SCOPE"` and `grep "multi-commit"` against this plan both return 0; the six lowercase "out of scope" hits are ordinary prose). **A session that comes here for that clause, finds nothing, and concludes the widening is already reflected in this plan would be wrong in the most expensive direction.** What plan 75's Phase 1 shipped: the clause is replaced, the introducing commit still anchors the window but now marks where it **STARTS** rather than where it ends, and a new Phase 2.5b step sweeps `git log <introducing-commit-sha>..HEAD` over the literal's own file **and** its Phase 2.4c inbound callers. **The consequence for THIS rule, which is why plan 75 touched it at all:** an introducing commit being a considered addition does not establish that the value still MEANS what it meant then — a later commit can change how the value is supplied without ever touching the literal. So this bullet's shipped form is **qualified by sweep outcome, not reversed**: the SHA-plus-subject citation bar stands unchanged, and the rule stays correct for a literal whose supply nothing later changed, which is the common case. **The near-identically-worded fix-layer `deliberate` twin is byte-unchanged** — plan 75 carved out the EVIDENCE-block bullet ONLY, and that carve-out is one of its shipped tripwire results.]**
- `migrated` / `generated` ⇒ no evidence-arm rule; the existing fix-layer rules are the only ones that apply, and they are inert when nothing is being replaced.

This is the rule that would have flipped the variant call: `is-variant-items` classifies `inherited-refactor` (TICKET-B restructured the parent and preserved the child's literal verbatim), so "its only caller passes `true`, therefore it is live" is exactly the inference the rule forbids.

**Counter (record it).** "Downgrade in confidence" is prose, not a gate — an LLM can record the row, write the rule's words, and keep the conclusion. True; the mechanical part of this plan is D4's EXISTENCE forcing, not conclusion correctness. Same honesty bound as check 19 (`main.md:518`).

## Build discipline

No phase is exempt.

**These are not a reading list. They are checks to run at four specific moments — DRAFTING, BUILDING, REVIEWING, CLOSING — and a session that reads all of them once at the start and never again has not applied them.** Every rule keeps its worked instance, because the instance is what makes it believable: a rule stripped to its statement is a rule that gets argued with.

**Routing (fixed, not learned).**

- `src/commands/research/main.md` and `src/commands/discover/main.md` ship into a consumer's `.claude/` → **instruction-author → instruction-reviewer + claude-code-guide**.
- Helper / setter / check changes under `src/devforge/lib/_research/` and `src/devforge/lib/_discover/` → **python-engineer → python-reviewer**, test-first, with fixtures round-tripped through the real setter → `verify` chain (never hand-authored report JSON).

### At DRAFTING — writing plan or spec text

- **Anchor on STABLE STRUCTURE, never on a line number and never on the wording you are about to change.** A line number in a plan is a claim with a short half-life: any phase that edits a file invalidates every line-number claim about that file below the edit point. Proof, not hypothesis — **seven re-keyings of the same anchors inside this one plan**: `:931` → `:939` → `:941` → `:961` → **`:975`**; `:992` → `:1000` → `:1002` → `:1024` → `:1035` → **`:1052`**; `:729-741` → `:729-749` → `:731-740` → **`:737`** (Phase 1's spec edit, Phase 2b twice, Phase 2a's `classify-finding-literal` insertion at +11 below Phase 2.6, the schema's own restructuring, and Phase 3's setter-8 insertion at +17 below `:1032`). **Those first two chains ended `:972` and `:1055` until a 2026-08-12 re-grep found the live file at `:975` and `:1052`; that is a CORRECTION, not an eighth re-keying — the record is in Phase 2b's anchoring note.** Anchor on a section heading, a step number, a fixed label; carry the number as a hint. **And do NOT anchor on the defect wording — that token dies the moment the scheduled edit fixes it**, exactly as "rejects a bug-mode report" died when 2b rewrote check 17's clause. **A quote of the defect is evidence of what was wrong, not a locator.**
- **WRITE so the unsafe reading is unreachable — the constructive form of the truncation test.** The reviewing rule asks *"is every fragment safe?"*; this asks *"is the unsafe reading reachable in ANY reading order?"* Two mechanics, both earned on Phase 4's honesty-bound sentence (`discover/main.md:534`): **put the duty a full sentence AHEAD of the thing that could be mistaken for it**, and **when the tempting answer appears, attach it to a prohibition** rather than leaving it free-standing. **This is not the truncation test restated** — that one catches a failure after it is written, this one prevents it while writing; a text can pass the check by luck and still be built wrong. Keep both. **Refinement earned in Phase 5: when a sentence must carry a QUALIFIED POSITIVE, the qualifier goes FIRST — a qualifier that trails is not read.** The defective original had the shape *[all-clear] — [justification] — [reassurance]*, so every early stop delivered the all-clear and no stop qualified it; the fix was purely ORDERING — the boundedness marker now precedes the claim, so no reading path reaches the positive statement without first meeting its bound.
- **When a work item MOVES between phases, its spec-side half moves with it.** A phase that ships a required CLI flag, a new verb, or a changed setter signature must ALSO own every `main.md` invocation template for that setter — and the phase's spec-loop scope line must be widened to NAME those sites. **A scope line naming a narrow line range is itself the hazard:** `:704-708` reads as precision while silently excluding sites the phase's own code change just invalidated. Not hypothetical — the 2026-08-12 resequence opened exactly the gap it was performed to close (OQ-5 build review, finding 1).
- **A scope boundary does not license leaving a sentence you know to be FALSE — fix it and flag the deviation.** Precedent, endorsed 2026-08-12: the Phase-2a spec author's brief forbade touching Phase 2.5b, but the new `classify-finding-literal` verb falsified two sentences the author had itself written EARLIER IN THE SAME PHASE — notably "there is no in-place repair… the only forward path is `reset-report`". It edited them anyway and **flagged the deviation rather than absorbing it silently**. Right precedence in both directions: a knowingly-false sentence outranks a scope boundary, and an out-of-scope edit is surfaced, never quietly folded in.
- **Plan vocabulary NEVER ships into a consumer's `.claude/`.** Plan-phase numbers ("Phase 2"), decision IDs (`D1`, `OQ-5`), and plan filenames are MAINTAINER-only. `src/commands/research/main.md` emits to `.claude/commands/devforge/research.md`, where a reader can resolve "Phase 2" only as `/research`'s OWN Phase 2 (Investigation) — plan 73 never reaches a consumer install at all. A consumer-shipping file may cross-reference only its own phases, steps, and check numbers. **This cuts against this plan's own habit of citing D-numbers when describing spec edits:** the citation belongs in the plan, never in the emitted text. It lives here rather than in a spec-author brief because the one observed violation originated in an orchestrator BRIEF (an instructed "see Phase 2" pointer the instruction-author correctly refused) — so it must be caught where briefs are written, not only where files are.
- Every load-bearing claim added to this plan during execution must carry a `file:line` anchor **or** be marked an open item. Do not invent verb names, flag names, check numbers, or SHAs.

### At BUILDING — making the change

- **ENUMERATE FROM THE NEW MECHANISM'S SCOPE — do not grep for old vocabulary.** Phase 2b's edit list said five sites; the real answer was eight, and it missed one for a reason no sweep could catch: `main.md:637`'s `record-finding` template was *correct* until check 20 existed, so searching for stale wording could never surface it. The question that finds it is **"what does check 20 gate?"** → every `findings[]` row → therefore every `record-finding` invocation template in the file → therefore both, not just the one in the section being rewritten. The two failure modes are DISTINCT and neither subsumes the other: `:706` is stale text with no searchable token (grep can't reach it), `:637` is correct text the new gate newly covers (grep has nothing to look for). Enumerating catches both; grepping catches neither.
- **For "have I found every call site," EXECUTION beats grep.** The sixth site in the Phase-3 counting episode (`test_plan_helper.py::_run_research_setup`) surfaced ONLY when a post-fix regression run failed 9 tests. No static grep found it, because the call matched no pattern anyone thought to search for. Run the suites and read the failures — a failing run enumerates what actually breaks, a grep enumerates what matches a guess.
- **When you build a repair path for one field, ENUMERATE its twins in the same package before closing.** A first-write-wins or append-only setter rarely has exactly one uncorrectable field. Phase 2 built `classify-finding-literal` for `rests_on_literal` and left `record-literal-archaeology`'s `--use` unrepairable **in the same package in the same week** — and the twin was found only by following a stale line number into an unrelated file.
- **A gate's remedy must satisfy EVERY downstream gate, not just its own.** When a violation message prescribes a fix, trace that exact prescribed string through every later validator before trusting it. Observed 2026-08-12 (Phase 4): Rule G's message says to cite the BARE path, `cmd_verify` accepts it, and the G-mirror in `PlanSeeds.__post_init__` then rejects it for lacking the full `internal:<path>` — **so following the gate's own instruction is what fails.** Paired sibling of the check-20 defect: there the remedy was impossible, here it is actively wrong. **A remedy is part of the contract and needs the same end-to-end proof the check does** — on the REAL path: the divergence hid for four plans because the tests called the builder directly and never crossed `cmd_verify` first.
- **When you decline work on COST grounds, MEASURE the cost — never reason by analogy from a real figure elsewhere.** Observed 2026-08-12 (Phase 3): an engineer declined the declaration-exists guard by analogy with this plan's own 74-call-site constraint. That figure was TRUE — of a different setter with a fundamentally wider blast radius. **The shape of the reasoning was sound and the fact was wrong**, which is the dangerous combination: it reads as rigour. Only counting caught it: `~40+` (accepted unchecked by the orchestrator) → **5** (reviewer, enough to overturn the decision) → **6** (exhaustive sweep). A cost-based refusal without a count is an assertion, not an analysis.
- **A precedent transfers with its INVARIANT, not with its shape.** Before copying a pattern, name the property that made it correct at the source and check it holds at the destination. `classify-caller-scope`'s blanket update is right because its key `(helper_qn, caller_qn)` denotes one call EDGE, whose duplicates share a true classification; `classify-finding-literal`'s `(surface, file_line)` is free text describing an OBSERVATION and carries no such invariant — copying the shape without the invariant is what let the repair setter fabricate a value (the MEDIUM in `### Phase 2a build review`).
- **STRUCTURED EVIDENCE and INTERPRETIVE PROSE are different artifacts for different readers — neither substitutes for the other, and neither is redundancy.** A structured row records *what was queried and what came back*; it has no field for *why the conclusion stands anyway*. **Two instances in this plan, both deliberate:** Phase 4's `## Absence Probes` table carries the git query and its result, while only the prose can say why the recommendation stands DESPITE a deletion being found; and the research side's `deliberate`-intent rule does the identical double-duty — a structured archaeology row PLUS a required SHA citation in the recommended-approach rationale. **Recorded as a pattern so a future session does not "de-duplicate" one half as redundancy** — dropping the table loses reproducibility, dropping the prose loses the reasoning, and each failure is silent.
- **Schema changes prove BOTH back-compat axes.** (a) The standard shape: old JSON → default + current-producer-stable, **no byte-identity claim** on new-producer output (plan 67 Phase 3 / plan 69 Phase 1b precedent). (b) **VALIDATION-WIDENING is a second, independent axis the standard clause does not cover** — "old JSON → default" proves NEW-FIELD DEFAULTING and says nothing about a previously-VALID field COMBINATION becoming invalid when a validator widens. `_specify/_cmds_handoff.py:437` reconstructs stored handoffs through `_dict_to_dataclass`, re-running `__post_init__` → `_validate_cross_field` on READ, so a widened validator breaks reads of files already on disk (Finding 2 in `## Phase 1 build findings + resequence`). **Axis (b) is proven at EVERY reconstruction call site, not just the loud one** — at least two exist in `_specify/_cmds_handoff.py` (`:437`, and `_try_research_hit()`, which swallows the failure), and the quiet one is the dangerous one.
- **When a brief describes what an UPSTREAM GATE guarantees, READ THE GATE — a summarised guarantee is a claim, not a citation.** Observed 2026-08-12 (Phase 5): twice in one paragraph an orchestrator brief supplied an upstream mechanism by summary rather than by reading it, and **both summaries were wrong in the same direction — overstating what the gate guarantees.** The direction is the tell: summaries drift toward "this is covered", because that is the shape a brief is trying to establish. - **A claim that repo capability is ABSENT must be verified exactly as hard as a claim about behaviour.** "The repo has no X harness / no such helper / no precedent" is a load-bearing negative: it licenses skipping work, or rebuilding what exists. **The sentence-level discipline does not catch it** — it is not a claim about the code under review, so no reviewer auditing the diff is looking at it. Observed 2026-08-12: a build report declined a race test because "the repo has no parallel-process harness", when `tests/lib/test_state_concurrency_stress.py` is precisely that harness. Grep before asserting absence — and when the decision survives the correction, **record the right reason**, because a wrong reason is reusable and a right one is not.
- **A negative result from the proxied `grep` is NOT evidence of absence.** The `rtk` hook's output is lossy: a reviewer hit a false "0 matches" across multiple files on 2026-08-12 and got correct counts only after switching to `command grep`. This compounds the rule above — the cheapest way to "verify" an absence claim is exactly the tool that silently reports false absences. **Re-run any zero-match through `command grep`**, and treat a proxied zero in a build report as unverified.

### At REVIEWING — auditing someone else's change

- **THE TRUNCATION TEST — apply it mechanically, not as a principle.** Read a paragraph only up to each full stop IN TURN, and at every stop ask: *what does this fragment ALONE tell a model trying to clear a gate?* **A period between a hazard and its correction is a defect regardless of how the paragraph reads whole.** Mechanical because the principle alone failed twice on a single sentence; the corrections landed at `main.md:754` and `:812`. A model under gate pressure stops reading at the first sentence that lets it proceed.
- **THE DIRECTION TEST — what scopes the truncation test so it does not flag everything.** Assert-then-retract is only a defect when **the misleading direction is the UNSAFE one**. Worked counter-example, deliberately unchanged: at `main.md:713` the truncated fragment misleads toward RUNNING AN EXTRA PROBE the same paragraph already sanctions — misleading, but safely, so not a defect. Without this test the truncation test flags every hedged sentence in the file. **Below-threshold candidate, CONSIDERED and judged, not missed:** the `deliberate` bullet of the evidence rule, where a comma-stop yields "the scope call may stand" before the "but" that adds the citation requirement. Recorded so a future session does not re-open it as an oversight.
- **Give reviewers the WHOLE diff, not just their lane's slice.** Cross-loop detection is a real safety net and the one that has actually fired here: a python-reviewer auditing blast radius noticed an unexplained `main.md` change and surfaced a skipped spec loop the spec lane, by definition, could not catch. A reviewer scoped strictly to its own files cannot see this class.
- **Real defects keep arriving sideways — treat an incidental anomaly as a lead, not a distraction.** Three times this session a genuine defect was found while chasing something else: a skipped spec loop found by a python-reviewer auditing blast radius; a missed edit site found by asking what check 20 gates; and the unrepairable `--use` twin found by **verifying a line number**. None came from the audit aimed at that defect. When a step turns up something unexplained, follow it before returning to the task. (Fires while building too — it is filed here because that is where the slack to follow a lead usually exists.)

### At CLOSING — declaring a phase or change done

- **A loop is not "the author ran" — dispatching instruction-author WITHOUT its reviewer is a half-applied discipline, and it counts as skipped.** Every `main.md` edit routes instruction-author → instruction-reviewer + claude-code-guide, including a one-paragraph follow-up. **This fails likeliest exactly there** — on an edit that feels too minor to route — and it is an ORCHESTRATOR failure, not an author's: the author cannot dispatch its own reviewer. Observed 2026-08-12 on the `--all` documentation paragraph, and caught only because a python-reviewer noticed `main.md` had changed with content that could only postdate the guard, then checked whether a spec-side pass had been logged — it had not.
- **SWEEP for what the landed decision falsified — outside the region anyone was looking at.** A landed decision reliably invalidates text nowhere near it. **Six instances in this plan**: Decisions (OQ-2 vs OQ-5), Phase bodies (the `handoff_schema` either/or), Context + When-resuming (D6's shelve prose after a BUILD pick), a `main.md` example stranded across a phase boundary, **the fix for that fourth instance producing the fifth** (adding `--use` grew the file and invalidated every line-number claim below it), and Phase 3's completion falsifying six in-flight descriptions at once. Re-sweep the WHOLE plan after every landed decision, resequence, or ratified pick — not just the paragraph the change was written in.

**Two overlaps worth naming rather than merging.** (1) The three enumeration rules at BUILDING rhyme but have different triggers: *enumerate from the mechanism's scope* covers what a new mechanism SHOULD touch, *execution beats grep* covers what it DOES touch, and *enumerate the twins* covers what a new repair does NOT cover. None subsumes another; a change can pass two and fail the third. (2) The DRAFTING anchoring rule and the CLOSING sweep rule come from the same episode — a landed edit moving line numbers — but fire at opposite ends: one governs how you WRITE an anchor, the other how you AUDIT after one moves. They were a single bullet until 2026-08-12 and were split deliberately, because a rule filed under "how to draft" is not read by someone declaring a phase done.
