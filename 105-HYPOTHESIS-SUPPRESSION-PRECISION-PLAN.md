`/devforge:research`'s `research_helper verify-hypothesis-suppression` gate over-fires, and — the finding that decides this plan's shape — it rewards obfuscation. Four findings were audited and every one was dispositioned **FIX** by the maintainer. This plan carries all four: a specificity floor plus evidence-grounded subtraction so a path segment or a generic word no longer weighs the same as a 21-character API identifier (Finding 1); label validation on the addressed-hypotheses fields, so the exemption the gate depends on cannot be silently lost (Finding 2) *(and, since the Phase 0 close on 2026-09-25, on the two not-covered fields too)*; the dissolution of the structural squeeze in which one check requires a qualified name in the rationale and the gate then refuses that same name (Finding 3); and the removal of the lexical exit, so rewording stops being the cheapest way out of an exit 2 (Finding 4).

### The four findings

**Finding 1 — HIGH — no specificity floor.** Any single shared token of four or more characters fires the gate (F2, F6). A path segment or a generic technical word weighs exactly as much as the long API identifier the gate was designed around. `pkg-alpha-core` tokenizes to `alpha` and `core` (`pkg` is three characters and is dropped by the length filter); `core`, `live`, `fields` and `declared` are in no stopword list (F6) and each fires the gate on its own.

**Finding 2 — MEDIUM — the addressed-hypotheses field is contractually labels and validated as free strings.** Three places state the label contract — the `record-hypothesis` docstring, the CLI help and the command spec's prose (F8, F10, F17) — and nothing enforces it (F9). The repo's own canonical test fixture writes cause text into that field and nothing goes red (F18). A model that does the same silently loses the gate's only exemption. This is the same class as the already-known failure mode in which green tests use a state shape the CLI cannot produce: here the tests inject labels directly into the report JSON, bypassing the setter, which is exactly why the fixture's violation is invisible (F19).

**Finding 3 — HIGH — structural squeeze.** On a tier-2 or tier-3 run, or whenever `probe_feasibility` is unresolved, no hypothesis is exempt (F3, F4). Check 2 requires the recommendation to declare at least one addressed hypothesis (F14). Check 11 requires the rationale to contain a recorded qualified name, evidence string or dead-sibling QN verbatim (F15). The gate then tokenizes that same rationale and refuses a shared token with any gated hypothesis's cause (F2). The qualified name is simultaneously required and forbidden. The two obligations report through different channels — check 11 inside `verify`'s accumulated violation list, the gate as its own separate verb (F16) — so the model sees two unrelated errors whose only joint solution is lexical.

**Finding 4 — HIGH — incentive inversion.** This is the finding that decides the plan's shape. The gate's only mechanical signal is vocabulary (F6). The cheapest action available to the party being checked is to change vocabulary. And the gate is documented (F5) **and unit-tested** (F22) to pass changed vocabulary. The emitted recovery recipe closes the loop: it instructs the model to re-call the setter with a rationale that "no longer encodes the unverified cause" (F21) — a semantic instruction checked lexically — under a three-iteration cap. Under a hard exit 2 the gradient therefore points at paraphrase rather than at re-reasoning, and the artifact that emerges is *less* legible than the one that went in: the mechanism still drives the design, merely unnamed. The repo's own sibling rule names this shape — *"a gate that silently disarms itself is worse than no gate"* (`90-E2E-TEST-LANE-PLAN.md`, about the regression-gate baseline).

### D5 — Keep the gate hard; remove the lexical exit

Finding 4 is resolved in favour of option **(c)**: the gate stays a hard exit 2 with its three-iteration cap, and on exit 2 **exactly two exits are admissible**:

1. **`record-gap`**, as today — move the mechanism into an open question and remove it from the rationale.
2. **An explicit declaration that the overlap is legitimate, anchored to a RECORDED evidence row.**

Rewording stops being the cheapest path, because it is no cheaper than the declaration and, unlike the declaration, **leaves no trail a reviewer can read.**

- **The declaration's shape (substance; OQ-1 decides its carrier).** It names three things: the hypothesis label whose overlap is accepted, the overlapping token or tokens it accepts, and a recorded evidence-row token the overlap is grounded in. **The helper refuses a declaration whose grounding token matches no recorded row**, printing the recorded tokens — the `--cites` shape (F13). The gate then treats the declared tokens of that hypothesis as accepted.
- **The declaration MUST reach the rendered report.** A conditional section in `research_helper render`, omitted entirely when there are none. ⚠ **Without it D5's own justification is false:** report state lives in `.devforge/` and does not travel, so a declaration recorded only in state leaves no trail in the artifact a reviewer opens. The section-order enumeration in the command spec (`research/main.md:1249`) is updated in the same pass.
- **The emitted text says the lexical exit is gone.** The recovery paragraph (`research/main.md:1241`) stops instructing a rationale rewrite as the ordinary remedy and names the two admissible exits instead.

**The zero-escape-hatch objection, argued head on rather than hidden.** The repo's meta-rule forbids any rule carrying *"'OR', 'if X except Y', 'use judgment', 'when reasonable', 'unless trivial', or any equivalent slip-path"*. A second admissible exit looks like an OR. It is not the forbidden shape, for one reason: **the forbidden shape is a JUDGMENT-shaped slip path, and this one is mechanical and falsifiable — the recorded row exists or it does not.** That is the same predicate `--cites` already enforces (`_cmds_approach.py:192-217`) and the same shape as the evidence-lane declaration this command already renders on every report (`research/main.md:1249`, *"listing each lane as `consulted` or `not consulted`"*). **It is a second mechanical predicate, not a carve-out.**

**Whether this breaks plan 75's tripwire, recorded and put to Phase 0.** The gate itself gains **no new way to fail** — the declaration only ever subtracts from the overlap, so the predicate is strictly more permissive and no new `verify-*` gate number and no new research check number is created. What is new is a setter that exits 2 on an ungrounded argument. **The narrow reading, which this plan RECOMMENDS: that is setter-side argument validation of the same class as `--cites`, not a validator over report state, so the tripwire holds in both halves.** The wide reading — any new hard-fail exit is an unnumbered validator — would make it a knowing, recorded break, in plan 91 D4's manner. Phase 0 rules; the build records which reading it ratified.

**RECOMMEND D5 as stated.**
