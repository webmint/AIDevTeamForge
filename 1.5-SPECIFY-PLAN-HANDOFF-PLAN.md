# 1.5 — Specify → Plan Handoff Plan

**Status:** DRAFTED 2026-05-22 on `develop-2.0-init`.

**Goal:** Add a structured producer-side handoff from `/specify` so `/plan` consumes it the way `/specify` already consumes research/discover handoffs. Closes the last asymmetry in the pipeline: `research/discover → specify` is structured JSON today, but `specify → plan` is manual prose (user copies a `/plan specs/NNN/spec.md` block across a CLI restart). After this plan the whole chain `research/discover → specify → plan → breakdown` carries machine-readable handoffs with auto-discovery and provenance.

**Why "1.5":** the specify *producer* genuinely goes first (spec precedes plan in the pipeline) and lands standalone — it just writes a JSON file next to the spec. The `/plan` *consumer* half cannot land until `plan_helper.py` is committed (it is CODE-EXISTS-UNTRACKED per `02-PLAN-COMMAND-REDESIGN-PLAN.md`). So this plan is two-staged: **producer now (Phases 0–3), consumer wired in `02`'s commit (Phase 4)**. Full alignment closes when 02 lands. 02 was paused mid-pickup to settle this contract first, so 02 will absorb Phase 4 rather than this plan racing ahead of it.

## Decisions locked with user (2026-05-22)

| Question | Decision | Rationale |
|---|---|---|
| Sequencing | **(a)** Producer-only now; consumer gated into `02` | Spec precedes plan; producer has no dependency, consumer needs untracked `plan_helper.py`. "Full alignment" closes at 02, not at specify alone. |
| Payload scope | **Rich** (structured spec snapshot + provenance) | "Consumer obeys producer" — producer owns shape, consumer conforms. Concrete payoff: `/plan` reads typed fields instead of regex-parsing `spec.md` (`pick-spec` currently scrapes markdown via `_parse_frontmatter_field` / `_count_acs` / `_STATUS_PATTERN`). |
| Carry `plan_seeds` (HOW)? | **No** | HOW is what `/plan` produces, not consumes. Research/discover carry `plan_seeds`; specify does not. Keeps the WHAT/HOW boundary clean. |
| `/plan` without a handoff | **Must still work** | Manual `/plan specs/NNN/spec.md` with no JSON falls back to current regex parse. Handoff is an enrichment, never a hard precondition. |

**Rich-field guardrails (must hold for every field added to the schema):**
1. Field exists because the **`/plan` consumer will read it** — not because specify happens to hold it. No dead schema.
2. Field is **reliably populated at `finalize` time** — a frequently-null field is worse than absent.

## Schema shape (proposed — locked in Phase 0)

`_specify/handoff_schema.py`, `HANDOFF_KIND = "specify"`, `SCHEMA_VERSION = "1.0"`:

```
Handoff:
  schema_version
  handoff_kind          = "specify"          # constant, enforced on read
  spec_path                                    # canonical artifact /plan reads
  specify_completed_at                         # ISO timestamp
  classification:
    spec_number, feature_name, feature_slug
    spec_type, spec_type_rationale
    status                                     # must be "Approved"
  spec_seeds:                                  # structured WHAT — replaces /plan regex scrape
    overview                                   # summary string
    acceptance_criteria  [ ... ]               # gives /plan AC count typed, not regex
    constraints          [ ... ]
    affected_areas       [ ... ]
    out_of_scope         [ ... ]
    open_questions       [ ... ]
    risks                [ ... ]
  provenance:                                  # research/discover → specify → plan chain
    upstream_handoff_path                      # from specify state source.handoff_path (nullable)
    upstream_handoff_kind                      # "research" | "discover" | null
    upstream_completed_at                      # nullable
  downstream_links:
    plan_path            = null                # /plan fills on completion
    execute_task_commit_shas = []
```

No `plan_seeds`. Provenance is nullable (specify may have been started without an upstream handoff).

**File layout:** `specs/NNN-<slug>/handoff.json` — nested per-feature, mirroring research's `research/<date>-<slug>/handoff.json` (the spec dir is already the per-feature container, so nested is the natural fit; discover's sibling-file layout is a worse match here).
