## Problem

`/devforge:constitute` Phase 6.2 (`src/commands/constitute/main.md:528-545`) runs `constitute_helper validate` — a 4-dimension weighted content-quality gate over `.devforge/constitute.json`. Dimension 2 (**citation validity**, weight 0.25) extracts path-like tokens from the constitution's rule text, table cells and code-example annotations and requires each to exist on disk.

That dimension systematically FALSE-POSITIVES on **naming-convention prose that the framework's own pipeline produces**. The misalignment is by construction, across three framework surfaces:

- `/devforge:generate-docs` Phase 4.3 captures a 6-bucket conventions structure whose first bucket is `naming` — `src/commands/generate-docs/main.md:438` (`{naming, file_organization, import_style, error_handling, styling, state_management}`).
- `/devforge:constitute` Phase 3 routes that raw `## Conventions` text into constitution §3 sub-sections and names "3.3 Naming Conventions" as an example sub-section — `src/commands/constitute/main.md:103` (sub-section list), `:105` (the conventions raw-text contract), `:122` (the `**Naming**` bucket → Section 3 routing rule).
- Phase 6.2 then extracts path-like tokens from exactly that prose and demands each exist — `src/commands/constitute/main.md:537` (the dimension's user-facing description), implemented at `src/devforge/lib/_constitute/_validate_metrics.py:221-293`.

A project whose naming conventions are filename-shaped (any component-per-file frontend layout) therefore fails a dimension whose content is correct, and the human `ship` override at `main.md:543` becomes the routine path — which erodes the gate's signal for its real target: genuinely hallucinated file references.

### Observed consumer failure (real run, 2026-08-17)

`composite=0.7955 FAIL`; `slot_fill 1.0`, `citation 0.1818` (2 resolved of 11 unique tokens), `code_syntax 1.0`, `rule_tag 1.0`. The arithmetic reproduces exactly from `_VALIDATE_WEIGHTS` (`_validate_metrics.py:40-45`): `0.30·1.0 + 0.25·0.181818 + 0.25·1.0 + 0.20·1.0 = 0.7955`. With the other three dimensions perfect, citation must reach **≥ 0.80** for the composite to clear `_COMPOSITE_PASS_THRESHOLD = 0.95` (`:48`).

The 9 unresolved tokens were: `index.ts`, `PageXxx.vue`, `.ts/.vue`, `PageCatalog.vue`, `UiXxx.vue`, `UiButton.vue`, `.spec.ts`, `/index.md`, `.devforge/session-state.md`. They fall into five distinct classes.

- **RC1 — convention placeholders.** `PageXxx.vue`, `UiXxx.vue`. Naming templates ("pages are named PageXxx.vue"). These can never exist on disk; the constitution rule stating them is correct.
- **RC2 — extension-only / generic pattern tokens.** `.spec.ts`, `/index.md`. `_PATH_TOKEN_RE` (`_validate_metrics.py:34-37`) requires only that a run of `[\w\-\./]` characters end in a known extension, so a token that is *nothing but* a dot-extension chain matches and is then demanded to exist.
- **RC3 — cross-slash regex artifact.** `.ts/.vue`. The character class `[\w\-\./]+` spans both `.` and `/`, so an unbackticked adjacent extension pair in prose joins into a single token that ends in a known extension and therefore matches. (The consumer's `constitute.json` is not in this repo, so the exact source prose was not inspected; the joining mechanism is derivable from the regex at `:34-37` alone.)
- **RC4 — real files nested below the install root.** `PageCatalog.vue` and `UiButton.vue` exist on disk, nested; `index.ts` is a barrel-convention token with a real stem that resolves the same way once the search is recursive (its presence in the tree is inferred from the stack, not verified — see Phase 5). None of these is an extension-only fragment, and filter (b)'s predicate does not catch them: they are resolved mechanically by Phase 2, never filtered. `_try_resolve` (`_validate_metrics.py:253-278`) has **no recursive search in standalone mode**: the two `rglob` fallbacks at `:264-277` are both inside `if effective_root is not None:`, and `effective_root` is non-`None` only when `init.yaml` declares `workspace_mode == "wrapper"` (`_resolve_effective_root`, `:183-200`). A standalone install gets exact-path checks and a package-basename lookup, and nothing else. Nothing in the code or its comments justifies the asymmetry.
- **RC5 — framework runtime files created later.** `.devforge/session-state.md` is written by `/devforge:implement` at runtime. A constitution rule instructing sessions to read it is correct; the validator only tests present-tense existence.

### Finding F1 — leading-slash tokens are checked against the filesystem root (latent bug, currently correct-by-accident)

`_try_resolve`'s first check is `(install_root_path / token).exists()` (`_validate_metrics.py:254`). For a token with a leading slash such as `/index.md`, `pathlib`'s `/` operator **discards the left operand when the right operand is absolute** — so the check is performed against the absolute path `/index.md`, not against `<install_root>/index.md`. The wrapper check at `:256` has the identical shape and the identical defect.

Today this always produces "unresolved", which is the outcome the token deserves for the wrong reason. It becomes a false **RESOLVE** the moment a same-named file exists at the machine's filesystem root. This is a real defect independent of the false-positive work and is fixed by D4.

## Decisions

- **D1 — Fix extraction and resolution; never move a threshold.** The false positives are extractor and resolver defects (RC1–RC5), and the fix belongs there. **Argument, mechanical:** `cmd_validate`'s exit code is gated on the composite alone (`_cmds_quality.py:95`), while `_DIM_PASS_THRESHOLDS` feeds only the per-dimension `"pass"` boolean in the stdout JSON (`:84`) — so raising citation's slop changes no pass/fail outcome at all, and the change would be pure theatre. Lowering `_COMPOSITE_PASS_THRESHOLD` blunts all four dimensions to fix one. Dropping citation's 0.25 weight redistributes to three dimensions that are already near-mechanical (`rule_tag` is enum membership; `code_syntax` is a parse). **Rejected:** (a) raise `_DIM_PASS_THRESHOLDS["citation"]` slop — inert, per the above; (b) lower `_COMPOSITE_PASS_THRESHOLD` — collateral; (c) delete Dim 2 — surrenders the hallucinated-citation catch, which is the dimension's whole purpose. **RATIFIED 2026-08-18: CONFIRMED as written.**

- **D2 — Filter placement is split: the leading-slash filter runs BEFORE resolution; the other three run AFTER a token fails resolution.** A token that resolves is counted resolved and is never classified. A token that fails resolution is classified, and a token matching a filter class is dropped from **both** numerator and denominator. **Argument:** the leading-slash filter is a resolution-CORRECTNESS fix (F1 — the join is wrong), so it must precede the join; the other three are classifications of *unresolvable* tokens, so running them after resolution costs nothing and preserves recall — a real file that happens to match a filter shape (a `.eslintrc.json` that exists, a real `XxxService.ts`) still counts as a resolved citation instead of vanishing from the score. **Rejected:** apply all four at extraction time — simpler and one code path, but it silently drops every real file whose *name* matches a filter shape, weakening the gate's real target for no gain on the false positives. **RATIFIED 2026-08-18: CONFIRMED as written.**

- **D3 — Four filter classes, each with an exact predicate.** Applied per D2. Each predicate is a single mandatory condition; none carries a judgment clause. **RATIFIED 2026-08-18: CONFIRMED as written.**
  - **(a) Placeholder** — the token contains the case-sensitive substring `Xxx`. Catches `PageXxx.vue`, `UiXxx.vue`. **Honest bound:** this is the observed placeholder vocabulary and nothing else — `Foo`, `MyComponent`, `<Name>` and every other convention vocabulary passes straight through. The filter REDUCES false positives; it does not eliminate them, and the `ship` reply at `main.md:543` remains the backstop for what it misses.
  - **(b) Extension-only** — the token contains no `/` **and** `Path(token).name` starts with `.`. Catches `.spec.ts` and a bare `.ts`. Does not catch `.devforge/session-state.md` (which fails both conjuncts). Breadth is OQ-5.
  - **(c) Leading slash** — the token starts with `/`. Pre-resolution per D2; the argument for exclusion over repair is D4.
  - **(d) Segment artifact** — the token contains `/` **and** at least one non-final segment is a pure-extension chain, where "pure-extension chain" means the segment starts with `.` and every dot-separated part after that leading `.` is a member of the extension vocabulary `_PATH_TOKEN_RE` is built from. Catches `.ts/.vue` (non-final segment `.ts`; parts `["ts"]` ⊆ vocabulary). Does not catch `.devforge/session-state.md` (`["devforge"]` ⊄ vocabulary) or `.github/workflows/ci.yaml` (`["github"]` ⊄ vocabulary).
  - **Single-sourcing requirement.** Predicate (d) needs the extension vocabulary as data. It is currently inline in the regex pattern string at `_validate_metrics.py:36`. Phase 1 extracts it into one named ordered constant that both the compiled regex and predicate (d) read. The extraction MUST preserve the existing order, because that order is load-bearing: the comment at `:30-33` records that longer suffixes come first so `tsconfig.json` is not extracted as `tsconfig.js`.

- **D4 — Leading-slash tokens are EXCLUDED, not repaired.** Filter (c) drops them; no code strips the slash and retries. **Argument:** `lstrip("/")` on `/index.md` yields `index.md`, which under D5's recursive resolution would then match *any* `index.md` anywhere in the tree — inventing a resolution for a token that is a regex artifact of a truncated path. Excluding it states the truth: the extractor produced a fragment, and a fragment is not a citation. Exclusion also closes F1 by construction, because no token reaching the `install_root_path / token` join can be absolute any more. **Rejected:** (a) strip the slash and resolve — manufactures resolutions; (b) leave F1 alone because it currently fails "correctly" — leaves a live false-RESOLVE path keyed on the machine's filesystem root. **RATIFIED 2026-08-18: CONFIRMED as written.**

- **D5 — Standalone gets the same recursive resolution wrapper mode already has, bounded by a directory exclusion set.** Both existing fallback stages move to a root-agnostic path so they run for standalone installs against `install_root` and for wrapper installs against `effective_root`: the exact-pattern `rglob(token)` stage and the slash-free `rglob("*" + token)` stage (`_validate_metrics.py:264-277`). Both stages gain a directory exclusion set (contents in OQ-2). **Argument:** the wrapper/standalone divergence IS the RC4 defect, and closing it by giving standalone *less* capability than wrapper would preserve the divergence in a new shape. **Honest cost, named:** the `"*" + token` stage is suffix matching, so a nonexistent `Foo.vue` resolves whenever any `MyFoo.vue` exists — that recall cost is imported from wrapper mode, not created here, and D5 accepts it in exchange for wrapper/standalone parity. **Rejected:** (a) give standalone the exact-pattern stage only — divergence persists, and it is the divergence that produced RC4; (b) leave standalone as-is and instruct constitution authors to cite install-root-relative paths — contorts the constitution's prose to suit a checker, which is D7's rejected shape. **RATIFIED 2026-08-18: CONFIRMED as written.**

- **D6 — Tokens inside the framework's own runtime namespace resolve.** A token whose first path segment equals `Path(devforge_dir).name` is counted as **resolved** (numerator), without a filesystem check. The prefix is derived from the `devforge_dir` argument `_count_citations` already receives (`_validate_metrics.py:221-232`), so no path literal is introduced. **Argument:** the framework owns that namespace and creates those files during the pipeline; a constitution rule citing `.devforge/session-state.md` is correct at authoring time and merely early. Counting it resolved is the semantically honest label — most `.devforge/` files (`memory.md`, `project-config.json`, `constitute.json`) exist at validate time and already resolve, so this decision only covers the runtime-created remainder. **Honest cost, named:** the exemption is namespace-wide, not file-wide — a genuinely hallucinated `.devforge/never-exists.md` citation resolves silently and never reaches `failed_items`. Dimension 2 therefore stops detecting hallucinated references inside that one namespace entirely, in exchange for never false-flagging a correct citation of a runtime-created file. Phase 0 weighs that trade explicitly; the rejected allowlist below is the alternative that keeps the detection and pays maintenance for it. **Rejected:** (a) a named allowlist of runtime filenames — stricter, but it needs maintenance every time the framework adds a runtime file, and a stale allowlist reintroduces exactly this false positive; (b) drop the tokens from the denominator instead — treats a correct citation as unclassifiable rather than as correct. **RATIFIED 2026-08-18: CONFIRMED as written.**

- **D7 — No producer-side rewording.** `/devforge:generate-docs`'s conventions capture (`generate-docs/main.md:438`) and `/devforge:constitute`'s §3 routing (`constitute/main.md:103,105,122`) are untouched. **Argument:** rewording naming-convention prose so it stops emitting path-shaped tokens contorts a consumer-facing artifact to appease its own checker, and it cannot work — constitution rule text is freeform LLM-composed prose, so no producer-side wording rule covers the general case. The checker is wrong here, not the prose. **Rejected:** (a) instruct the producer to backtick or otherwise escape filename patterns — backticks already fail to prevent RC1/RC2/RC5 (a backticked `PageXxx.vue` is still extracted verbatim), so the escape does not even solve the observed cases; (b) add a "do not cite filenames in conventions" rule to §3 composition — deletes correct content to protect a metric. **RATIFIED 2026-08-18: CONFIRMED as written.**

The index changes the matching semantics for the exact-pattern stage (a basename index cannot answer a multi-segment pattern such as `src/components/Foo.vue`), so it is not a drop-in. - **OQ-4 — Should wrapper mode's existing unbounded `rglob` gain the same directory bounds?** This is a **behavioral change for wrapper installs** (a token resolvable today only via a file inside `node_modules` stops resolving), so it is not a silent refactor. - **OQ-5 — Is filter (b)'s predicate the right breadth?** As written in D3(b) it also matches real dotfiles with extensions (`.eslintrc.json`, `.prettierrc.json`). If ratified, Phase 1 owns the code emission (threading `filtered_items` through `_count_citations`'s return value and `cmd_validate`'s `result_obj`) and Phase 4 owns the docs consequence (`main.md:534` gains the key in its output description). **RATIFIED 2026-08-18: YES — `cmd_validate`'s stdout JSON gains a `filtered_items` key listing each dropped token with its filter class.
